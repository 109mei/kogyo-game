# SPEC — 工業ゲーム（仮称 NAGANO INDUSTRIES）

## 1. 概要と今回の範囲

「自分の手で始めた仕事を、少しずつ人・機械・会社そのものに任せながら、巨大な産業システムへ育てる」縦画面の産業経営シミュレーション。
1つの会社・1つの世界を何十〜何百時間も育て続ける。周回・リセットはしない。

今回のMVPで作るもの（企画書 94 の13機能すべて）

| # | 機能 | 実装 |
|---|---|---|
| 1 | 資源採取 | 施設カードの［採取する］をタップすると10秒（×1）で原料が入る |
| 2 | 手動生産 | 加工・組立も手作業で1回ずつ作れる |
| 3 | 従業員配置 | 週ごとに来る応募者から雇い、施設へ配置。熟練度・得意分野あり |
| 4 | 工場生産 | 施設は 手作業 → 機械化 → 自動化 と同じ施設のまま育つ |
| 5 | 在庫 | 会社全体の倉庫。生産・消費・差引・在庫切れ予測 |
| 6 | 市場売買 | 価格は需要と供給で動き、自社の売買にも反応する。長期契約あり |
| 7 | 電力 | 系統電力の契約と自社発電所。不足すると全工場の効率が落ちる |
| 8 | 条件付き自動化 | 運営方針（かんたん）／在庫しきい値（標準）／条件式（上級） |
| 9 | 研究 | 研究所と研究員。産業の解放と既存事業の改善 |
| 10 | 財務 | 日次の収支、月次の推移、借入 |
| 11 | 時間加速 | ⏸ ×1 ×4 ×12 ×48。重大問題で自動停止 |
| 12 | 通知 | タップで該当画面へ移動 |
| 13 | サプライチェーン表示 | 縦の階層で素材を掘っていける |

内容は企画書 62〜70 の100項目すべて（原料15・中間素材20・部品15・完成品15・施設35）。最初に見えるのは10項目前後で、研究と目標で少しずつ開く。

M&A・株式・子会社・海外・製品設計・顧客層は後回し（画面には「準備中」として出さない）。

## 3. ルール

### 3.1 時間
- ゲーム内の1日 = ×1 で実時間60秒（`balance.time.realSecondsPerDay`）。速度は ×1 / ×4 / ×12 / ×48
- ルール本体は 1日 = 240刻み（6ゲーム分）で進める。乱数は種つき（sfc32）。同じ種と同じ命令列なら同じ結果
- 閉じていた間は同じ刻みでまとめて進める（既定の上限30日、設定で 0/7/30/90日）。重大問題が出たらそこで止める
- 開始日 2027年4月1日

### 3.2 資源の流れ
- 施設は1つのレシピを選んで動く。入力は会社の在庫から取り、出力は在庫へ入れる
- 1バッチ = 作業員1人の1日分の仕事。機械1台は1日に `machineRate`（既定20）バッチ、自動機は `autoRate`（既定22）
- 手作業：配置した作業員1人ごとに1日1バッチ×熟練度×得意分野。社長（あなた）はタップで 1/6 日分を作る
- 機械化：機械1台に作業員1人（操作員）。電力を使う
- 自動化：人は不要。電力が多く、設備費が高い
- 規模（Lv）で最大人数・最大台数が増える
- 効率 = 電力充足率 × 物流充足率 × 管理係数 × 研究の補正 ×（工場長の補正）。稼働率として表示
- 倉庫が満杯になると、重さが増えるレシピは止まる

### 3.3 価格と市場
- 基準価格はレシピから決まる：`(入力の基準価格の合計 + 付加価値) ÷ 出力量`。付加価値は recipes.json にある
- 市場価格 = 基準価格 × 価格指数。価格指数は、外部の需要変動（平均回帰する乱数）と、自社の売買量（7日平均）÷ 市場規模 で決まる：`((D)/(D + 自社の純販売))^(1/弾力性)`
- 買いは +6%、売りは −4% の手数料。一度に大量に売買すると、その場で価格が動く
- 長期契約：毎日一定量を固定価格で購入／販売（期間7〜90日）

### 3.4 人
- 応募者は毎週月曜に来る（人数は本社Lvと研究で増える）。役割：作業員・研究員・技術者・工場長
- 熟練度★1〜5。働いた日数で上がり、給与も上がる。得意分野（採取・加工・製造・研究・管理）で +12%
- 給与は月給を日割りで毎刻み支払う。解雇は1か月分

### 3.5 電力
- 需要 = 動いている機械の消費電力の合計。供給 = 系統契約 + 自社発電所
- 契約：低圧50kW / 高圧500kW / 特別高圧5,000kW（基本料金 + 従量料金）
- 発電所：石炭・天然ガス・燃料で発電（在庫から燃料を使う）。安いが建設費が高い
- 不足時は全工場の効率が 供給÷需要 になる

### 3.6 物流
- 運ぶ量 = トラック輸送の品目の生産量と購入量（重さ）。水・原油・天然ガスはパイプラインで対象外
- 能力 = 本社の基本 + トラック（自社の小型トラックを在庫から配車、無ければ市場で購入）+ 物流センター
- 不足すると効率が 能力÷需要 になる。運賃は重さに比例

### 3.7 管理
- 本社Lvごとに管理能力がある。施設1つ = 1、社員20人 = 1。工場長のいる施設は 0.3
- 超えると全体の効率が落ちる（最大 −30%）。本社を拡張するか工場長に任せる

### 3.8 自動化（条件付き）
- 施設ごとに 自動運転 ON/OFF と運営方針：在庫安定 / 利益優先 / 生産優先 / 省電力 / カスタム
- 難易度3段階：かんたん（方針だけ）、標準（在庫 < A で生産・> B で停止）、上級（AND条件 → 生産率 0〜150%）
- 条件に使える値：在庫、在庫日数、市場価格指数、需要指数、利益率、電力使用率、電力単価、資金
- 自動売買：品目ごとに「在庫が X を超えた分を売る」「Y 未満なら買う」と価格の上下限
- 工場長を置くと、その施設の調達と販売も自動になり、効率が上がる

### 3.9 研究
- 研究所に研究員を置くと研究点（RP）がたまる。1研究員 = 1RP/日 × 熟練度
- 研究は1つずつ。産業の解放（製鉄・窯業・非鉄・石油化学・電機・電子・電池・車両ほか）と改善（速度・省エネ・省材料・物流・管理）

### 3.10 財務
- 日次：売上、材料費、人件費、電力費、物流費、維持費、利息。投資（建設・設備）は別に記録
- 借入：上限は純資産に応じて、年利3%。返済はいつでも。資金がマイナスだと当座貸越（年利10%）
- 企業価値 = 純資産 + 年間利益 × 5（利益が正のとき）

### 3.11 問題と対処（ホームの中心）
毎日、問題を計算して重さ順に出す。1つの問題に複数の解決手段を出す（「工場を建てれば正解」にしない）。

| 問題 | 対処の例 |
|---|---|
| 素材不足（在庫切れまでN日） | 市場で購入 / 長期契約 / 生産施設を建設 / 使う側を減産 / 省材料の研究 |
| 電力不足・逼迫 | 契約変更 / 発電所建設 / 省電力モード / 省エネ研究 |
| 人手不足・待機社員 | 採用 / 自動配置 / 自動化 |
| 倉庫満杯 | 倉庫建設 / 在庫を売る / 生産調整 |
| 物流逼迫 | トラック追加 / 物流センター / 研究 |
| 資金 | 借入 / 在庫売却 / 赤字施設の停止 |
| 赤字施設 | 停止 / 利益優先モード |
| 管理能力超過 | 本社拡張 / 工場長を置く |
| 研究が止まっている | 研究テーマを選ぶ |

### 3.12 命令の一覧
`gather`（手作業）/ `build` / `upgradeSize` / `buyMachine` / `automate` / `setRecipe` / `hire` / `fire` / `assign` / `autoAssign` / `promote` / `sell` / `buy` / `contract` / `setAutoTrade` / `setAutomation` / `setPowerContract` / `setPowerPlant` / `addTruck` / `research` / `borrow` / `repay` / `upgradeHQ` / `rename` / `setSpeed` / `dismissNotice`

### 3.13 乱数を使う箇所
応募者の生成（名前・役割・熟練度・得意・給与）、市場の需要変動、施設の地名。

## 4. 数値

すべて `src/data/*.json`（Zodで読み込み時に検査）。コードに数値を書かない。

- `balance.json` 時間、開始資金、給与、電力、物流、市場、財務、管理、問題のしきい値
- `items.json` 65品目（単位・重さ・市場規模・輸送方法・解放）
- `recipes.json` 65レシピ（入力・出力・付加価値・電力倍率）
- `facilities.json` 35施設（建設費・日数・維持費・手作業/機械/自動の各値・規模）
- `research.json` 研究（費用・前提・効果）
- `goals.json` 次の目標（順番・条件・解放）

## 6. セーブ

- localStorage のキー `kogyo-game/save`。窓口は `SaveStore` だけ
- 中身：`{ version, savedAt, state }`。`state` はルール本体の状態そのもの（JSONにできる形）
- 版番号 `SAVE_VERSION`。古い版は `migrations.ts` で順に変換する
- 10秒ごと・画面を離れたとき・重要な命令のあとに保存
- 設定からテキストで書き出し・読み込み（機種変更用）
- 閉じていた間の上限：既定30日（設定で変更）

- すべてタップで完結。スワイプ・長押しは使わない（将来の便利機能に留める）
- 戻るはヘッダーの ← とブラウザの戻る
- 数値は ［-］［+］ と +100 / +1,000 / MAX

## 8. 見た目の決まり

- 明るい背景に白いカード。素材画像は白背景で描かれているため、明るい面で最もきれいに見える。ダークテーマも用意
- 書体はシステムの日本語ゴシック1つ。数字は等幅数字
- 色の役割：🟢正常 #16a34a / 🟡注意 #d97706 / 🔴要対応 #dc2626 / アクセント（操作）#2563eb

- 文字を減らす：まずアイコンと数字、タップで内訳

## 10. 企画からの変更・改善点

| 変更 | 理由 |
|---|---|
| 施設は建て替えず、同じ施設が 手作業→機械→自動 と育つ | 「昨日まで自分でやっていた仕事」が同じカードの上で変わっていくのが見える。施設の歴史（建設年・累計生産）も続く |
| 応募者は週ごとに限られた人数 | 人を増やすだけで無限に伸びないようにし、「人が足りない → 機械化」の必然を作る |
| 本社の管理能力 | 企画の「工場数が増える → 管理が問題になる → 管理職に任せる」をそのままルールにした |
| 物流のトラックは自社製品（小型トラック）を配車 | 自社の完成品が自社の物流を支える循環 |
| 基準価格をレシピの付加価値から計算 | 100項目の価格が矛盾しない。レシピを変えても価格が追従する |
| 閉じていた間も会社が回る（上限つき、重大問題で停止） | 核の体験「自分なしで回っている」を、戻ってきた瞬間の報告で見せる |
| ホームに工業地帯の3Dジオラマ（Three.js、設定でOFF可） | 施設が増えるほど街が育ち、煙やトラックで「動いている」ことが一目で分かる。操作はカードのまま |
| PixiJS は使わない | 動く2D世界が主役ではない（企画86）。3D表示だけ Three.js を遅延読み込み |
