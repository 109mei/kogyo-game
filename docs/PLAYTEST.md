## 見つけて直した不具合

| 不具合 | 影響 | 修正 |
|---|---|---|
| 放置時間が0.25日（×1で15秒）未満だと、計算ごと捨てていた | 別アプリに少し切り替えるたびに時間が失われる | 短い不在も必ず計算し、報告だけ1日以上で出す |
| 2つのタブで開くと、古いタブが後から保存して新しい進行を上書きしうる | セーブが巻き戻る | 保存に「どのタブが書いたか」を添え、別タブが保存したら止まって「こちらで続ける」を出す |
| 自動運転の条件の数値欄で小数が打てない（「18.5」→185） | 条件が気づかずに10倍ずれる | 入力中の文字を保ったまま、数として正しいときだけ反映する欄に変更 |
| 研究所がないのに研究員が応募してくる（応募者の約2割） | 働けない研究員を雇い、給料だけ払って資金が尽きる | 研究員は研究所（建設中を含む）ができてから応募 |
| 建設命令に施設と無関係な作り方を渡すと例外 | 画面からは起きないが、ルール本体の入力検査もれ | 施設が作れない物なら断る |
| 生産画面：施設が多いと、全カードを毎秒10回作り直していた | 施設152で×12でも操作不能 | 25施設以上は種類ごとにまとめて表示（タップで展開）、カードは表示が変わったときだけ描き直す。×12で詰まり133%→5% |

あわせて：応募者カードに「空いている持ち場がありません（雇うと待機になり給料だけかかります）」と役職ごとの空き数を表示。

## 問題がなかったこと

- 自動保存（10秒ごと）、再読み込み直後の保持、書き出し→読み込み
- 放置の上限（20日／7日／0日の設定どおり）、読み込み時間 約0.4秒（700日目）
- 壊れたセーブ・新しい版のセーブは最初の画面で理由を出し、セーブを消さずに残す
- セーブの大きさ：200日 223KB、700日 368KB、1080日 588KB（上限約5MBに対して十分）
- 数量を打ってすぐ［売る］を押しても、打った数量で売れる

## 序盤のつまずき（設計の課題）

画面の目標どおりに進めるプレイヤーを2通り再現した。

- **素朴なプレイヤー**（応募者は全員雇い、在庫は売らない）：13日目に資金がマイナス、29日目に倉庫が満杯。
  在庫は767万円分あるのに資金は−465万円で止まる。自動停止と問題カード（銀行から借りる・在庫を売る）は出ている。
- **普通のプレイヤー**（空きの分だけ雇い、在庫はこまめに市場で売る）：製材所・組立工場・研究所を建てるたびに資金が底をつく。
  研究所の直後は資金がマイナスで研究員を雇えず、169日目まで研究が始まらなかった（借入に気づけば抜けられる）。
- 自動プレイ（`tools/bot.ts`）は投資の順番と手元資金を計算して進めるので、この問題が見えにくかった。

## 改善案（優先度順）

下の7つはすべて実装した（次の節）。

1. **余った在庫を1タップで売る**：入力に使う分（例：3日分）を残して、ほかを市場の1日の規模まで売る。
   資産画面と「倉庫が満杯」「資金がマイナス」の問題カードに置く。序盤の手作業の売却と、倉庫満杯の停止をまとめて解消する。
2. **目標の達成報酬（補助金）**：序盤の目標に50万〜300万円。目標に沿うほど資金繰りが楽になり、建てるたびに資金が底をつく問題を和らげる。
3. **建設シートで「建設後の資金」と「給料の何日分が残るか」を表示**し、少なければ警告する。
4. **部門長・子会社**（企画の「工場長→部門長→子会社」の続き）：種類ごとのまとめ表示を「部門」にし、部門長が在庫目標・採用・機械の追加を任されて回す。終盤の手間を減らし、管理の問題に新しい解決策を足す。
5. **受注とイベント**：期限つきの注文（例：自転車500台を30日で、報酬＋20%）や、停電・ストライキ・災害などの選択つきイベント。中盤以降の目標を増やす（アイコンは素材にある）。
6. **計算をWeb Workerへ**：施設150・×48ではスマホ相当でCPUの約4割を計算に使う。ルール本体は画面を知らないのでそのまま移せる。
7. 序盤の採取10秒を短くする（または連続で押せる）、次に押すボタンを光らせるなど、最初の数分の案内を強める。

あわせて見つけて直したもの
- 研究所の完成で研究員が応募するとき、応募者の上限（24人）を超えることがあった（ファズテストで発見。以前からの不具合）
- 品薄の出来事で「買いだめ」を選ぶと、見積もりの額を購入代金とは別にもう一度払う作りになっていた（見直しで発見）
- 子会社の最初の作業場（Lv0）が「満杯」の判定を妨げ、子会社が工場を建てられなかった（見直しで発見）
- 工場長・自動売買が注文の分まで1時間ごとに市場へ売ってしまい、自動プレイでは受注の7割が未達だった → 納品を1時間ごと（市場へ売るより先）にし、注文の残りは売らない。未達 96件 → 3件（1080日）
- 部門長の「現金が固定費30日分を割るときは使わない」が大きな会社では厳しすぎ、採用も投資もしなかった → 10日分に（1080日の自動プレイで発見）
- 計算を別スレッドにした直後は、閉じる直前の最大2秒の進行が保存されなかった → 閉じる瞬間に画面側の写し（常に最新の状態と一致することをテストで確認）を保存
- 子会社の施設にも手作業のボタンが出ていた。資金が大きいとヘッダーの金額が2行に折り返していた（画面の確認で発見）
